# ScopeAnalyser — Initial Plan (2026-06-03 18:09)

Three-tools-in-one desktop app for TwinCAT ADS users: Signal Recorder, Analyser,
Data Converter. Each tool usable standalone or together in a shell window.
Recorded data is immediately available to the Analyser via a shared in-memory
`SignalStore`.

## Confirmed decisions

- **Language**: C++20.
- **UI**: Qt 6.7+ (Widgets, not QML).
- **Build**: CMake >= 3.24 + vcpkg, Ninja generator. Presets for
  `linux-{debug,release}` and `windows-{debug,release}`.
- **OS targets**: Linux AND Windows. Single ADS code path via the Beckhoff/ADS
  open-source library (`github.com/Beckhoff/ADS`, MIT). The `IAdsClient`
  abstraction stays so TcAdsDll can drop in later if needed.
- **Plotting**: QCustomPlot 2.x (adaptive sampling, multi-pane linked cursors).
- **Math parser**: exprtk (vectorized over arrays).
- **Storage**: HDF5 via HighFive (chunked, zstd or gzip-compressed datasets per
  channel).
- **Excel**: QXlsx.
- **CSV**: `<charconv>` + memory-mapped file (`QFile` + mmap).
- **Threading**: lock-free SPSC queues from moodycamel; HDF5 writer on a
  background thread.
- **Tests**: GoogleTest.
- **Logging**: spdlog.
- **Licensing**: LGPL deps accepted (Qt, QCustomPlot, QXlsx).
- **Repo**: separate GitHub repo `ScopeAnalyser`, mirroring the layout pattern
  of the user's other projects, with `_ClaudeMemory/` and `_PlansAndExecution/`
  folders committed alongside the source.

## Strict scope rule

**No PLC-side code.** ScopeAnalyser is a pure client. There is no helper FB, no
ST library, and no link to `Frameworks_For_PLC`. It is a standalone repository.

## Physical sampling reality

Client-side only, two real acquisition modes:

| Mode | Source | Typical max rate |
|---|---|---|
| `AdsNotify` | any symbol; ADS device notifications at parent task cycle | 1 ms (typical), down to 100 µs |
| `Oversampled` | `ARRAY[0..N-1]` already exposed by a TwinCAT oversampling terminal or fast task | terminal rate (down to ~10 µs) |

The 10 µs spec is reachable only via `Oversampled` mode. Arbitrary internal PLC
variables are bounded by their task cycle.

## Phase 1 exit criteria

- CMake skeleton builds end-to-end (all subdirs link) on Linux and Windows.
- ADS connect + symbol upload + per-symbol parent-task cycle discovery work
  against a real TwinCAT system.
- `NotifyChannel` records 100 channels at 1 ms for 5 minutes into HDF5 with
  zero lost notifications, surfacing any overrun as a visible warning.
- Live preview plot in the Recorder shows a 5-second ring of all active
  channels.

## Phase roadmap

1. Recorder core (`NotifyChannel` end-to-end, HDF5 sessions, basic UI).
2. Oversampled mode + plotting polish (adaptive sampling, linked cursors).
3. Analyser (exprtk engine, function library, formula editor + autocomplete).
4. Converter (Excel + CSV sources, drag-mapping UI, `.scaconv` profiles).
5. Polish: triggers, session metadata UI, additional sources/functions.
